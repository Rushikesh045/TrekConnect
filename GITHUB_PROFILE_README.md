### 🏔️ Featured Architecture: TrekConnect Platform

> **Repository**: [github.com/Rushikesh045/TrekConnect](https://github.com/Rushikesh045/TrekConnect)  
> **Architecture Style**: Microservices, Event-Driven Saga, Database-per-Service, Dual-Tier Concurrency

```
                        ┌────────────────────────────────────────────────────────┐
                        │                Angular 18 Frontend Client              │
                        │           (Role-Gated Routes & Interceptors)           │
                        └──────────┬─────────────────────────────────┬───────────┘
                                   │                                 │
           POST /auth/* (Port 8080)│         POST /api/* (Port 8081) │ (Bearer Token)
           (RS256 JWT Issuance)    ▼                                 ▼
                    ┌────────────────────────────┐    ┌────────────────────────────┐
                    │      trekconnect-auth      │    │      trekconnect-core      │
                    │    (Identity & Access)     │    │     (Business Domain)      │
                    └──────────────┬─────────────┘    └──────────────┬─────────────┘
                                   │                                 │
                     JDBC (Port 5432)                  JDBC (Port 5432)
                                   ▼                                 ▼
                    ┌────────────────────────────┐    ┌────────────────────────────┐
                    │    PostgreSQL (auth_db)    │    │    PostgreSQL (main_db)    │
                    │   - users_credentials      │    │   - treks, events, bookings│
                    │   - refresh_tokens         │    │   - seat_locks, outbox     │
                    └──────────────┬─────────────┘    └──────────────┬─────────────┘
                                   │                                 ▲
                                   │ AMQP: UserRegisteredEvent       │ AMQP Listener
                                   └────────────► [ RabbitMQ ] ──────┘
                                                 auth.exchange
                                                       ▲
                                                       │ Distributed Locks (TTL 10s)
                                             ┌──────────────────┐
                                             │  Redis 7 Cluster │
                                             └──────────────────┘
```

#### Key Technical Highlights & Design Invariants:
1. **Asymmetric Identity & Zero Secret Sharing**: `trekconnect-auth` signs tokens using a 2048-bit RSA Private Key (RS256). `trekconnect-core` retrieves the public key via `/.well-known/jwks.json` and verifies signatures locally without cross-service network calls or shared symmetric secrets.
2. **Two-Tier Concurrency Defense**: Eliminates double-booking during flash-sale surges via **Redis Distributed Locks (`SETNX`)** combined with **JPA Optimistic Locking (`@Version`)** and automated Spring Retry.
3. **Orchestrated Saga Pattern**: Manages the seat reservation lifecycle across states (`PENDING_PAYMENT` $\rightarrow$ `CONFIRMED` / `CANCELLED` / `EXPIRED`). A background daemon reclaims seats and issues compensating updates for unpaid bookings after 10 minutes.
4. **Transactional Outbox Consistency**: Eliminates dual-write inconsistencies by committing domain events (`OutboxEvent`) in the same database transaction as business entities, with a scheduled publisher polling and dispatching to RabbitMQ.
5. **Financial Security**: Integrated Razorpay payment gateway with cryptographic HMAC-SHA256 signature and webhook verification to prevent tampering.
